Reverse Mortgage Modelling & Simulation

An end-to-end model linking stochastic interest rates, mortgage amortisation, house-price uncertainty and retirement equity withdrawals.

Simulation1,000 house-price paths
ToolsExcel · VBA
HorizonAge 30 to 95
View model logic & VBA

01

The question

The project asked how a mortgage and later-life equity-release strategy could behave when both borrowing rates and property values are uncertain. I built one connected model to examine repayments, outstanding balances, withdrawals and the equity remaining at the end of the horizon.

My role

I designed the spreadsheet logic, implemented the stochastic processes and amortisation schedule, wrote VBA to run and store 1,000 simulations, created the charts, and documented the assumptions and limitations.

03

Stochastic rates and loan dynamics

I used a Cox–Ingersoll–Ross process to generate mean-reverting nominal rates, converted those rates to the selected payment period, and rebuilt the repayment schedule at each step. A dropdown changed the frequency and VBA displayed the relevant section of the schedule.

Monthly outstanding balanceIllustrative cached simulation · starting balance $1.008m
Balance

The changing composition of each repayment was an important validation check: early payments were predominantly interest, while principal became the larger component as the balance reduced.

04

House prices and equity release

The second half of the model simulated property values with stochastic volatility. VBA recalculated one path at a time and stored 1,000 paths, which were then summarised using the median, mean and a log-price distribution.

  1. 1
    Generate correlated shocks

    Two random shocks drove changes in variance and house price at each fortnightly step.

  2. 2
    Store the paths

    A VBA loop copied each recalculated path into a 1,000-column results sheet for later aggregation.

  3. 3
    Apply the withdrawal rule

    Withdrawals began at age 67, accumulated with interest and were checked against the modelled property-value cap.

  4. 4
    Summarise the range

    I used both central estimates and the full distribution because the long horizon created a strongly right-skewed outcome set.

What the model showed

Accrued balance$4.795m at age 95

Interest compounding created a material gap between cash withdrawn and the final reverse-mortgage balance.

Decision insight

The model is most useful as a scenario engine, not a point forecast. It shows how repayment timing, rate assumptions, withdrawal design and long-term property growth interact—and where product sustainability is most sensitive.

06

Validation and model risk

I used balance run-off, repayment composition, frequency comparisons and distribution charts as reasonableness checks. Reviewing the workbook again for this portfolio also exposed improvements I would make before using it for a real decision.

Reproducibility

The model uses volatile random-number formulas without a fixed seed. I would move the random-number generation into controlled code so results can be reproduced.

Long-horizon calibration

A fixed 9.55% annual drift over 65 years produces extreme right-tail property values. I would recalibrate the assumptions, add regime scenarios and report real rather than only nominal outcomes.

Summary-cell audit

The original summary label for the final outstanding balance referenced cumulative withdrawals rather than the interest-accrued balance. I identified the correct balance during this review and would add automated reconciliation checks.

Product realism

Fees, borrower behaviour, mortality, changing interest rates and policy constraints were simplified. These would be essential extensions for commercial use.

07

Reflection and next iteration

This project taught me that building a large model is only half the work. A useful actuarial model also needs controlled assumptions, reproducible runs, transparent checks and outputs that can be explained to a decision-maker.

What worked
  • Connected multiple financial components
  • Automated 1,000 simulation runs
  • Used charts as reasonableness checks
  • Documented assumptions and limitations
What I would improve
  • Separate inputs, calculations and outputs more clearly
  • Add a fixed seed and scenario controls
  • Build formula and reconciliation tests
  • Recalibrate the long-term property model

60-second interview explanation

“I built an Excel and VBA model that connected a CIR interest-rate process to a mortgage amortisation schedule, then simulated 1,000 stochastic house-price paths and applied a retirement equity-release strategy. The main technical challenge was managing a long simulation horizon while keeping the cash-flow logic auditable. When I revisited the model, I also found a summary-cell reference issue and an assumption that created extreme long-term outcomes. That review reinforced an important lesson for me: model governance and validation matter just as much as implementing the mathematics.”
